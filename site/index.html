Can network position predict which gene pairs kill a cancer cell?

A reproduction and stress test of MAGICAL, a classifier that uses protein-protein interaction (PPI) network features to label gene pairs as synthetic lethal, synthetic viable, or neither. The goal is to check how well the published results hold up, then test how fragile they are.

What gets implemented

Five stages, in order. Each later stage depends on the one before it.

  1. Rebuild the feature pipeline

    Pull the labelled gene pairs and PPI network from the paper's repository and database. Re-extract the network features, checking each against the code's output.

  2. Recreate the published evaluation

    Use the same train/test split and metrics as the paper. Report the gap between my numbers and theirs before changing anything.

  3. Compare with simpler models

    Logistic regression, random forest and gradient boosting on the same features, plus network-only heuristics such as degree product and shortest-path distance.

  4. Perturb the network

    Remove random nodes or edges, rewire while keeping degrees, and re-score. See how fast performance drops.

  5. Shortlist candidate pairs

    Rank pairs the model predicts confidently and consistently across perturbations, as leads for biological follow-up.

Background: why gene pairs matter

Two genes are synthetically lethal when losing either one alone is survivable but losing both kills the cell. This matters for cancer because a tumour often has one gene already broken. A drug that hits its partner can then kill tumour cells while leaving healthy cells, which still have both genes, largely alone.

The best-known example is BRCA-deficient tumours treated with PARP inhibitors. Finding more pairs like this by experiment is slow, because the number of possible gene pairs is enormous. That is the gap computational prediction tries to fill.

Synthetic viability is the opposite surprise: a loss that would normally hurt the cell is rescued when a second gene is also lost. Predicting both, plus the ordinary "no interaction" case, makes this a three-way classification problem rather than a yes/no one.

Evaluation plan

With three classes and probably far more "other" pairs than lethal ones, plain accuracy can look good while the model misses most real lethal pairs. So every result gets reported per class.

  • Per-class precision, recall and F1 show where the model fails, especially for the rare classes.
  • Macro-F1 averages F1 over classes so the large class cannot hide weak ones.
  • Matthews correlation coefficient summarises the whole confusion matrix in one number that is hard to inflate.
  • Confidence intervals from repeated seeds or bootstrap resamples, so small gaps are not over-read.

How the data gets split

How pairs are divided into train and test sets can change the answer a lot. The paper's split is reproduced first, then the stricter ones are added.

SplitHowWhat it tests
Published splitAs in the paper and repositoryWhether the reported numbers can be matched
Random pairsShuffle pairs, repeat over several seedsSpread between runs
Gene held outNo gene in the test set appears in training pairsWhether the model learns real network signal or just memorises genes
Source held outTrain on one data source, test on another, if availableGeneralisation beyond the original labels

Robustness protocol

Each perturbation is applied to the network only, then the features are recomputed and the same trained model is scored again. Every setting is repeated over many random seeds and reported as a curve with an interval, not a single number.

PerturbationHowWhat it reveals
Remove nodesDelete 5% to 30% of genes at randomSensitivity to missing proteins
Remove edgesDelete 5% to 30% of interactions at randomSensitivity to an incomplete network
Add noise edgesInsert random false interactionsSensitivity to false positives in the network
Degree-preserving rewiringSwap edge endpoints, keeping every gene's degreeWhether results come from wiring or just from degree
Swap the networkRebuild features from a different interaction databaseDependence on one data source

The rewiring row is the sharpest test. If performance barely changes when only degrees are kept, the model is mostly learning degree.

From predictions to candidates

  • Keep pairs predicted with high confidence and the same class across most perturbations.
  • Remove pairs that already appear in the training labels, since those are not new.
  • Cross-check against public resources: existing synthetic lethality databases, CRISPR dependency data such as DepMap, and the literature.
  • Look for pathway themes among the top pairs instead of trusting single pairs.
  • Report them as hypotheses, with the evidence for and against each one.

Risks and how they are handled

RiskMitigation
Repository dependencies are old or fail to installPin versions in a clean environment; note every fix
Published numbers cannot be matched exactlyReport the gap honestly and list what differs
Rare classes have few examplesPer-class metrics, repeated seeds, intervals
Well-studied genes dominate the network and the labelsGene-held-out split; check performance by degree bucket
Interactions depend on cell type and contextState the limitation; do not claim clinical relevance
Information leaks from test to trainingFix splits once, save them, never tune on the test set

Reproducibility checklist

  • Record the repository commit and every package version.
  • Fix and log random seeds.
  • Save the exact train/test pairs used for every table.
  • Keep original-paper numbers and my numbers in separate files and separate figures.
  • Write each experiment's question before running it.

Glossary

PPI network
A graph where genes or proteins are nodes and physical interactions are edges.
Synthetic lethal
A gene pair where losing both is fatal but losing one is not.
Synthetic viable
A gene pair where a harmful loss is rescued by losing the second gene.
Knockout
Switching a gene off so its protein is no longer made.
Node and edge
A gene, and an interaction between two genes.
Centrality
A score of how important a node's position in the network is.
Macro-F1
F1 averaged equally over all classes.
Data leakage
Test information sneaking into training, making results look better than they are.
Rewiring
Randomly swapping edges while keeping each node's degree.

Questions

Is this a new discovery?

No. Reproducing a published model confirms or questions the original claims. The new part is the stricter generalisation and robustness testing, reported separately.

Why CPU only?

The method uses classical machine learning and graph statistics, which run on an ordinary laptop. Start with a small subset to check everything works before the full run.

What if I cannot match the paper's numbers?

That is still a result. Document the gap, check data versions and split details, and report what differs rather than tuning until the numbers agree.

Can predictions be used clinically?

No. They are hypotheses for lab follow-up, not evidence about treatment.

Where do I start tomorrow?

Clone the official repository, create a clean environment, read how the features are built, and run the smallest example end to end.

Knockout screen simulator: where synthetic lethality comes from

Genes often back each other up. In this toy cell a nutrient flows through steps to biomass, and the cell lives as long as any route still works. Click genes to knock them out and watch the green path, or click a square in the grid to test a pair. The grid is a full double-knockout screen: every pair, computed instantly.

Synthetic lethal pairs come from redundancy, but a network feature only sees that indirectly. The averages above often overlap between the two groups, which is one reason predicting these pairs from network structure is hard.

An abstract model: a cell lives if a route survives. Real cells add context, timing and rescue effects (synthetic viability is not modelled here). The same screen runs in Python with src/knockout_screen.py in the zip.

Null lab: is a pair closer than its degrees explain?

Features like shared neighbours go up simply because both genes have many partners. To check, this lab compares your pair with 300 networks rewired to keep every gene's number of connections but scramble who connects to whom. If the pair is no closer than that null, a model using the feature may only be reading degree. Paste any interaction list, such as a subset of a real PPI network. It runs in your browser and nothing is uploaded. It starts with the toy network.

These are generic pair features, not MAGICAL's own feature set. The same idea runs on a real network with src/degree_null.py in the zip. The all-pairs scan works for networks of up to 40 genes.

Shortcut lab: can a model pass without learning the biology?

A model can score well by learning which genes tend to be lethal, instead of what makes a particular pair lethal. A random split hides this, because the same genes appear in training and test. A gene-held-out split exposes it. This lab simulates both on invented data. Drag the first slider and watch the memoriser's score fall apart on unseen genes.

Synthetic data: 80 invented genes, all 3,160 pairs, the top quarter labelled lethal, scores averaged over a handful of random runs. The memoriser has no features, so on genes it has never seen it can only guess. This is a simulation to explain the risk, not a result about MAGICAL. In the real project the gene-held-out split and the degree-preserving rewiring play this role.

What this project does and does not claim

Reproducing a published model is not a new discovery. The contribution here is an independent test of how well MAGICAL generalises and how robust it is to changes in the network. Those results will be reported separately from the original paper's numbers, and predicted pairs are hypotheses until tested in the lab.
